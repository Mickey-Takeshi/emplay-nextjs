## 0. 方法と、この監査で言えないこと

**一次データ**
- 本番 `https://emplay.jp` の sitemap掲載317URLを全件取得したHTML
- Supabase `emplay_hp.blog_posts` の記事原文294本

**ローカルの `.next` ビルド成果物は使っていない。** 本番と内容が食い違うことを確認したため
（例: `content-marketing-strategy-guide` のリンク先が、ローカル成果物では存在しない `/blog/ga4-guide`、
本番では正しい `/blog/ga4-analytics-guide` だった）。ビルドキャッシュが古いページを再利用していたと見られる。

**記事本文の精読**はカテゴリ別に10並列で全294本を読み、severity=high の指摘は別エージェントが
原文に当てて反証を試みた（**24件を棄却**）。生き残った指摘のうち、事業影響のあるものは
さらに本監査で原文を grep して再確認している。

### 言えないこと（重要）

**Google Search Console のデータは含まれていない。** GSC用のMCPコネクタが接続されておらず、
`gcloud` のADCにも `webmasters` スコープがないため、実際の検索順位・表示回数・CTR・
クエリ別の流入は一切見ていない。したがって本書は**サイト側の状態の分析であって、成果の分析ではない**。

以下のいずれかを用意いただければ、実データと突き合わせた分析を追加できる。
- GSCのサービスアカウントJSON（`sc-domain:emplay.jp` に閲覧権限を付与）
- claude.ai の Search Console コネクタ接続

**とくに「検索意図の重なり（共食い）」は、GSCのクエリ別データがないと最終判断ができない。**
本書の24組は本文を読んだうえでの推定であり、統合・削除の実行前にGSCで各記事の獲得クエリを
確認すること。

## 1. P0 — 事業影響あり・即対応

### 1-1. 本文が生HTMLのまま表示されている記事が2本

`ReactMarkdown` に `rehype-raw` を入れていないため、Markdownでなく生HTMLで書かれた記事は
タグが**文字としてそのまま画面に出る**。本番HTMLで確認済み。

| 記事 | HTMLブロック数 | 状態 |
|---|---|---|
| `/blog/listing-ads-bidding-strategy` | 89 | 全文が `<p>…</p>` のまま表示 |
| `/blog/meta-ads-conversion-tracking-optimization` | 117 | 同上 |

見出しが認識されないため目次が出ず、H2構造も検索エンジンに渡っていない。本文中の表もテキストとして表示される。

**対応**: この2本の `content` をMarkdownへ変換してDBを更新する（他292本と同じ書式に揃える）。
`rehype-raw` を全体に入れる案は、294本すべてのレンダリング挙動が変わるため採らない。

なお `seo-technical-optimization-guide` と `web-accessibility-guide` にも生HTMLが出るが、
**どちらもコードブロック内のサンプルコードで表示は正常**（検知の誤りだったことを確認済み）。

### 1-2. HP制作の価格がサービスページと矛盾している

`seo-writing-guide` の自社サービス紹介ブロックに次の記述がある。

```
### 料金

- HP制作:100万円〜
- 継続コンテンツ作成:月20万円〜(10記事)
```

直後に `/service/hp` へリンクしているが、そのページの正は **初期45万円〜**。
読者はサービスページの2倍以上の金額を見てから遷移することになる。
2026-09-01のレビューで「30万円」の誤りを一斉修正した際に、この箇所は対象から漏れている。

**対応**: 45万円〜に修正し、金額の直書きをやめて `/service/hp` の料金表を参照させる。

### 1-3. Markdownのリンク記法が壊れていてCTAが不通の箇所が4つ

角括弧が抜けており、`こちら(/contact)` が本文にそのまま表示されている。クリックできない。

| 記事 | 該当 |
|---|---|
| `inbound-tourism-readiness` | `ホームページ制作サービス(/service/hp)` と `こちら(/contact)` の2箇所 |
| `exhibition-booth-lead-followup` | `こちら(/contact)` |
| `owned-media-startup` | `こちら(/contact)` |

**対応**: 4箇所を `[こちら](/contact)` 形式に修正。あわせて `(/`で始まる裸のパスを全記事で機械検索し、再発を防ぐ。

### 1-4. 根拠のない成果数値を表で掲載している

`seo-writing-guide`:

| 期間 | コンテンツ数 | 効果(平均) |
|---|---|---|
| 12ヶ月後 | 120記事 | 検索流入10倍、月間問い合わせ10件以上 |

`line-official-account-guide` にも業種別の「来店数2倍」「再来店率30%向上」の表がある。
どちらも対象・期間・母数・計測方法の記載がない。

自社の `ai-citation-content-structure` が「実在しない事例や成果数値を作ってはいけない」と
明記している方針と矛盾する。実測値があるなら条件を注記し、出せないなら表を外す。

## 2. P1 — 構造上の問題

### 2-1. ほぼ全記事のタイトルが検索結果に収まっていない

`<title>` は「記事タイトル | 株式会社EMPLAY」（サフィックス10字）。本番実測:

| | 値 |
|---|---|
| `<title>` 全体 | 最小38 / 最大76 / 平均47.0字 |
| 40字超 | **286本（97%）** |
| 45字超 | 134本 |
| 記事タイトル本体のみ | 平均34.0 / 中央値32 / 最大63字 |

日本語SERPの表示上限は概ね30〜32字。最長は76字（`image-generation-ai-business-guide`）。

**対応**: タイトル本体を28〜32字に収め、主要キーワードを前方に置く。
70本分の書き換え案を付録Aに掲載した。

### 2-2. FAQ構造化データが1本も出ていない

記事のJSON-LDは `Article` + `BreadcrumbList` + `Organization` + `WebSite` の4種のみ（294本すべて同じ）。
一方で **250本が `## よくある質問` + `### Q...`／`### 質問文` という機械的に解析可能な書式**でFAQを持っている。

`/service` 配下には `FAQPage` を出しているのに、ブログには出していない。
リッチリザルトとAI検索での引用機会をそのまま逃している。

**対応**: `lib/` にFAQ抽出関数を作り、`app/blog/[slug]/page.tsx` で `FaqJsonLd` を出す。
既存の `components/FaqJsonLd.tsx` がそのまま使える。書式が揃っているので実装は機械的に済む。

### 2-3. サービスページからブログへの導線がほぼゼロ

ヘッダ・フッタを除いた、各ページからブログ記事への本文リンク数:

| ページ | ブログ記事へのリンク |
|---|---|
| `/service/hp` | 1本（`aio-llmo-seo-guide` のみ） |
| `/service` | **0** |
| `/service/ads` | **0** |
| `/service/crm` | **0** |
| `/service/creative` | **0** |
| `/company` | **0** |
| `/`（ホーム） | **0** |

ブログ→サービスは122記事から出ているのに、逆流がない。
「`/service/ads` は69本のマーケティング記事に支えられている」というトピック上の関係が、
検索エンジンにもAI検索にも見えていない。

**対応**: 各サービスページに「関連する記事」ブロックを置き、そのサービスに対応するカテゴリの
主要記事4〜6本へリンクする。カテゴリページ（`/blog/category/marketing` 等）へのリンクも添える。

### 2-4. 記事末CTAの穴

CTAコンポーネントはカテゴリからサービスを引く。その結果:

| カテゴリ | 本数 | CTAのサービスリンク先 |
|---|---|---|
| AI活用 | 68 | **外部の `academy.emplay.jp`**（自サイト内リンクにならない） |
| セキュリティ | 12 | **なし** |

AI活用68本は記事数最大のカテゴリでありながら、内部リンクとしての価値をサイト外へ流している。
セキュリティ・補助金の17本は `/contact` しか出ない。

**対応**: AI活用は `/service/crm` か `/service/hp` を内部リンクとして併記したうえでACADEMYを外部リンクにする。
セキュリティは `/service/hp`（サイト保守・セキュリティ）、補助金は `/service` を割り当てる。

### 2-5. 本文でサービスに言及しているのにリンクしていない記事が18本

記事末で「EMPLAYの広告運用サービスで支援しています」等と書きながら、リンクを張っていない。機械検出。

### 2-6. 本文の日付と構造化データの日付が食い違う記事が50本

本文に「本記事の情報は◯年◯月時点」と書いた記事が84本ある。内訳は **2025年1月が50本**、2026年1月28本、2026年7月6本。
一方 `updated_at`（＝JSON-LDの `dateModified`）は275本が2026年7月。

つまり50本は、**本文が「2025年1月時点」と言い、構造化データが「2026年7月更新」と言っている**。
読者にもクローラにも不整合で、更新日だけを進める運用に見える。

**対応**: 中身を見直した記事は注記も更新する。体裁だけの更新なら `updated_at` を進めない運用に改める。

### 2-7. サムネイル294本すべてがUnsplashからのホットリンク、ユニークは83枚

1枚を28記事が共用している。`og:image` も同じURL。SNSやSERPでの識別性がなく、外部ホストに依存している。
2026-05のリニューアルで全ストックフォト廃止としたが、ブログには適用されていない。

**対応**: 少なくとも被リンク上位・流入上位の記事から順に自社画像へ差し替え、自ドメインで配信する。

### 2-8. 出典リンクが244記事（83%）でゼロ

本文の外部リンクは延べ245本だが、うち `academy.emplay.jp` 50本、`images.unsplash.com` 30本（画像）。
**実質的な出典リンクは165本程度**で、大半の記事は一次情報を指していない。
出典先は mhlw.go.jp 11、openai.com 10、chusho.meti.go.jp 10、ipa.go.jp 4 など。

AIO/LLMOをサービスとして販売している以上、ここは説得力にも直結する。
なお **`/llms.txt` は404**。自社サイトに未設置。

## マーケティング（69本）

69本は「2025年1月公開のHTML記事群（約30本）」と「2026年5〜7月公開のMarkdown記事群（約38本）」の2層に明確に分かれており、後者は一次情報リンク・数値の留保表現・自社の経験則を含む質の高い記事が揃う一方、前者は※注記が「2025年1月時点」のまま更新日だけ2026年7月に進んでおり、AIモデル名・Cookie規制・Search Consoleの機能・ツール名（Pardot、CMS Hub）などが古いまま残っている。構造面では、後発の個別テーマ記事（google-review-increase-guide、efo-form-optimization、line-ads-guide、yahoo-ads-guide等）が、既存のハブ記事（meo-optimization-guide、cvr-conversion-rate-guide、line-official-account-guide、listing-ads-optimization-guide）から本文リンクを受けておらず、被リンク0〜2本のまま孤立している。加えてMEO/GBP、AIO/ゼロクリック、Facebook広告/Instagram広告、広告運用代行/広告代理店選びの4組で検索意図がほぼ完全に重なっている。最も緊急度が高いのは、seo-writing-guideのCTAに残る「HP制作:100万円〜」という誤った価格（同カテゴリのseo-article-outsourcing-guideでは45万円〜と明記）と、2記事で壊れているCTAリンク（「こちら(/contact)」がプレーンテキストのまま表示されている）である。
