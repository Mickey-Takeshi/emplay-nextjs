# LLMO診断レポート（llmocheki.com）の検証と改善計画

対象: https://emplay.jp/ ／ 診断レポート: https://llmocheki.com/llmo/report/255 ／ 検証日: 2026-08-07

外部の自動診断ツールによるレポートを、**本番サイトで1件ずつ実測検証**した記録と、そこから導いた改善計画。
指摘の一部は事実と異なるため、対応不要なものを先に切り分けている。

---

## 1. 最重要の構造理解 — 内部改善だけでは46点が上限

総合スコアの内訳は以下の加重平均になっている。

| 区分 | 配点 | 現在 | 寄与 |
|---|---|---|---|
| サイト内部の対応 | 40% | 85点 | 34点 |
| **AI引用の実測** | **60%** | **10点** | **6点** |
| **総合** | | | **40点** |

つまり、**サイト内部を満点(100)にしても総合は 46点にしかならない**（100×0.4 + 10×0.6）。
一方、AI引用を50点まで上げれば、内部が現状85のままでも **総合64点**になる。

> **結論**: HTMLの細かい修正は「安く早く終わるので当然やる」が、スコアと実利（AI経由の指名流入）を動かすのは §4 のAI引用施策。ここを主戦場と考える。

## 2. 誤検知（対応不要 — 実測で問題なしを確認）

診断ツールの指摘のうち、以下は**事実と異なる**。修正すると逆に品質を落とすものも含むため、対応しない。

| 指摘 | 診断の判定 | 実測結果 | 判断 |
|---|---|---|---|
| **サイトマップ参照なし** | 0/7 ✗ | `robots.txt` に `Sitemap: https://emplay.jp/sitemap.xml` を**記載済み**（curlで確認） | 誤検知 |
| **コンテンツ圧縮なし** | 0/5 ✗ | `content-encoding: br`（Brotli）で配信中。42KB → 10KB に圧縮されている | 誤検知（診断側が Accept-Encoding を送っていない可能性） |
| **パンくずナビゲーション欠落** | 0/5 ✗ | 診断対象は**トップページ**。トップにパンくずが無いのは正常な設計。下層ページには `Breadcrumb` コンポーネントが入り、BreadcrumbList 構造化データも出力済み | 誤検知 |
| **画像alt属性 0%** | 0/7 ✗ | トップの `<img>` は1種類（記事サムネイル）のみ。**リンク内にタイトル `<h3>` が同居**しているため、`alt=""` がアクセシビリティ上の正解（altを入れると読み上げが二重になる） | 誤検知。スコアのためにa11yを崩す価値はない |
| **INP/FID 101ms** | 3/7 ✗ | Google の INP 基準では **200ms以下が「良好」**。101ms は良好域 | 過剰指摘。優先度最低 |
| **日付シグナル欠落** | 2/5 ✗ | ブログ記事・一覧は `datePublished`/`dateModified` を出力済み。トップページに無いだけ | ほぼ誤検知（トップに記事日付は不要） |

## 3. 実在する内部の問題（P0 — 安く確実に直る）

| # | 問題 | 実測での確認 | 対応 | 工数 |
|---|---|---|---|---|
| **P0-1** | **セキュリティヘッダー未設定** | レスポンスに `X-Content-Type-Options` と `X-Frame-Options`(または CSP `frame-ancestors`) が**無い**。あるのは HSTS のみ。`next.config.ts` に `headers()` 定義なし | `next.config.ts` に `headers()` を追加（nosniff / frame-ancestors / Referrer-Policy / Permissions-Policy）。academy側の `vercel.json` に既に同等の設定があるので揃える | 0.5h |
| **P0-2** | **llms.txt が無い（404）** | `https://emplay.jp/llms.txt` → 404 | 会社概要・サービス・料金・主要記事へのリンクを構造化した `public/llms.txt` を新設。AIクローラに「何の会社か」を明示できる | 1h |
| **P0-3** | **モバイルの文字が小さい** | 375px幅で実測: 本文 **13.1px** が多用、リード文 11.3px、チップ 10.3px。37要素が14px未満 | 本文を 15〜16px 相当へ引き上げ（`--font-size-*` の見直し）。読了率にも効く | 2h |
| **P0-4** | **タップターゲットが小さい** | 44px未満が **24件**。「VIEW MORE →」が高さ22px、ハンバーガー40px、ヘッダーナビ43px | 最低44×44pxを確保（paddingで拡張。見た目を変えずに当たり判定だけ広げられる） | 1.5h |
| **P0-5** | **記事サムネイルがJPEG配信** | Unsplash画像が `image/jpeg` 111KB。`&fm=webp` を付けると **WebP 99KB**（-11%）で配信される | サムネイルURL生成時に `fm=webp` を付与（表示側で付けるだけ。DB書き換え不要） | 0.5h |

**P0合計: 約5.5時間**。すべてコードだけで完結し、素材待ちなし。

## 4. 本丸 — AI引用の実測が10/100（配点60%）

### 現状の内訳（レポート実測）

| 質問タイプ | ChatGPT | Gemini | Claude | AI Overview |
|---|---|---|---|---|
| 指名検索（「EMPLAYのサービス内容」等 2問） | ✓ 言及 | ✓ 言及 | ✓ 言及 | ✗ 未出現 |
| **カテゴリ・課題解決型（6問）** | **✗** | **✗** | **✗** | **✗** |

**社名を出せば認識されるが、「中小企業 ホームページ制作」のような"指名なし"の質問では一切出てこない**。これは記事本数（294本）の問題ではなく、AIが引用先として選ぶ条件を満たしていないことを示す。

### AIが引用先に選ぶ条件と、EMPLAYの現状

| 条件 | 現状 | 打ち手 |
|---|---|---|
| **① Bingインデックスにある** | ChatGPTのWeb検索はBing索引に依存。IndexNowは稼働済みだが **Bing Webmaster 未登録**（保留中タスク#10） | Bing登録（5分・GSCインポート）。ユーザー作業 |
| **② 第三者からの言及がある** | 自社サイト以外での言及がほぼ無い。AIは「複数ソースで確認できる事実」を優先する | 比較ポータル掲載（発注ナビ/Web幹事/アイミツ等）、PR TIMESでのリリース、Googleビジネスプロフィール開設 |
| **③ エンティティが一貫している** | **`sameAs` 未設定**（公式SNS/GBPのURLが構造化データに無い）。AIが「同一企業」と束ねられない | 公式SNS・GBPを用意し `sameAs` に列挙（素材待ち・progress-log §4 S-6） |
| **④ 一次情報・独自データがある** | 価格の数値開示は実施済み（強み）。一方、**自社調査データ・実績数値・事例が無い** | 独自調査（例: 中小企業のAI利用実態100社調査）を1本作る。/works事例ページ（素材待ち） |
| **⑤ 回答として抜き出しやすい形式** | 記事はFAQ・比較表を持つものと持たないものが混在。トップは `table` 2/4・`details` 2/4 の評価 | 主要記事の冒頭に「結論」ブロック、比較表、FAQ（FAQPage構造化）を標準化 |
| **⑥ そもそも検索で上位にいる** | AI Overviewは通常検索の上位を土台にする。カテゴリKWでの順位が未確認 | GSCで対象KWの順位を確認し、上位化余地のある記事から強化（**GSCはMCP/API経由で。ブラウザ操作はしない**） |

### 優先順（費用対効果順）

1. **Bing Webmaster 登録**（ユーザー作業5分） — ChatGPT経由の露出の前提条件。すでに保留タスク化済み
2. **Googleビジネスプロフィール開設 + 公式SNS整備 → `sameAs` 実装** — エンティティ確立の最短路。素材（アカウント）さえあれば実装は1時間
3. **主要サービスLP・上位記事の"AI回答フォーマット"化**（結論先出し・比較表・FAQ構造化） — 自社だけで完結。10ページで2〜3日
4. **独自調査コンテンツ1本** — 引用される一次情報を自前で作る。企画〜公開で3〜5日
5. **第三者掲載**（比較ポータル・プレスリリース） — 費用と営業判断が伴うため要決裁
